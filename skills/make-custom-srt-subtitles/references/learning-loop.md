# 人工回填與持續學習制度

收到剪輯師人工修正過的 SRT 時完整讀取本文件。目標是讓一次修正立即保護該集，讓重複模式逐步改善 Skill，同時避免單一剪輯師或單次例外污染全域規則。

## 目錄

1. 最少操作協議
2. 持久化檔案
3. 差異分析
4. 學習層級
5. 升格與降級
6. 多剪輯師治理
7. 回歸測試
8. 回報格式

## 1. 最少操作協議

首次交付時：

1. 建立唯一 `job_id`。
2. 保存不可覆寫的 `<job_id>_AI基準.srt`。
3. 交付 `<job_id>_人工校對用.srt`。
4. 保存 `<job_id>_job.json`、本集 `decisions.json`、來源版本及製作模式。

人工校對者只需修改「人工校對用」SRT 並傳回。檔名保留 `job_id`；可在結尾加校對者，例如 `<job_id>_人工修正_小楊.srt`。沒有校對者名稱時記為 `unknown`，不要因此阻塞回填。

收到回填時，依 `job_id` 取回基準稿。若基準稿不存在或工作編號不明，才請對方補傳 AI 原稿；不要要求重新敘述字幕規則。

## 2. 持久化檔案

不要依賴聊天室訊息保存學習狀態。每個工作至少保留：

- AI 基準 SRT：不可覆寫，供日後差異比較。
- 人工修正版 SRT：保留原檔。
- `<job_id>_job.json`：記錄工作編號、節目、集數、AI 基準檔名與雜湊、來源檔案、製作模式、建立時間和所有回填版本。
- `decisions.json`：本集精確鎖定、hidden events、講者警示與人工確認。
- `feedback.json`：由差異工具產生的結構比較及後續人工分類。
- `series-profile.json`：節目專有名詞、固定人物與只適用該節目的例外。

採用「一個系列一個聊天室、一集一個獨立工作編號」：

- 同系列可集中在同一聊天室，延續講者、詞彙、節目梗與字幕偏好；不同系列或客戶另開聊天室。
- 每次新集都建立新的 `job_id`、獨立目錄、`job.json` 與 `decisions.json`。聊天室相同不代表工作相同。
- 在 `<job_id>_job.json` 記錄 `series_id`、`episode_id`、本集來源白名單、來源雜湊與版本。只有白名單內的本集檔案可以參與製作。
- 不得跨集沿用音檔、影片、SRT、時間碼、音訊事件、講者時間表、hidden events、speaker checks、待確認項目、exact 鎖定、AI 基準稿、人工稿或字幕成品。
- 只從 `series-profile.json` 載入可跨集知識。即使舊附件仍在同一聊天室或工作區，也不得當成本集素材。
- 新聊天室可繼續同系列，但要用 `series_id` 讀取同一份 `series-profile.json`；不得要求使用者靠重述全部舊對話維持規則。

每個 `series-profile.json` 只保存：

- `series_id`、系列名稱與別名。
- 已確認的固定講者、角色與穩定的講者名稱對照。
- 專有名詞、固定用語、節目梗及常見誤辨識對照。
- 只適用該系列的字幕偏好、錄音習慣與可信證據。
- 更新時間、來源 `job_id` 與確認狀態。

不要在 `series-profile.json` 保存任何單集時間碼、逐句 exact 鎖定、待確認答案、來源附件路徑或整份字幕內容。單集資訊只留在該 `job_id` 目錄。

Skill 內只保存短小、可重用的規則與聚合證據。不要把完整節目 SRT、音檔或大量逐句差異塞進 Skill。

在支援持久化檔案的 Work Mode 中，將上述檔案存入 `字幕學習/<節目>/<job_id>/`。若環境沒有持久化儲存，首次交付時把 AI 基準稿與工作紀錄一併提供給使用者備份；仍只要求剪輯師日常回傳人工修正版。

## 3. 差異分析

先執行：

```bash
python3 scripts/revision_report.py \
  <job_id>_AI基準.srt \
  <job_id>_人工修正版.srt \
  --job-id <job_id> \
  --reviewer <校對者或unknown> \
  --out <job_id>_feedback.json
```

工具只建立時間重疊、文字、分段與起訖變動的客觀報告。接著用原音、分軌、ElevenLabs 原始 JSON 與前後文，把每組差異標成：

- `recognition`：一般辨識錯字或漏字。
- `proper_noun`：人名、品牌、作品、英文或固定詞。
- `format`：繁簡、空格、標點、大小寫、符號、實體換行或強制換行標記。
- `filler_reaction`：語助詞、回答或拉長反應的刪留。
- `laugh_sound`：笑聲與其他非語言聲音。
- `stutter_repeat`：結巴、重啟或有意義重複。
- `speaker_overlap`：講者歸屬、串音、插話或重疊取捨。
- `segmentation`：切句、合併、話語邊界、詞彙被拆開或語意斷點不自然。
- `start_timing`：第一個保留字的開口點。
- `end_timing`：字幕消失、停頓或下一句銜接。
- `hidden_event`：不上字幕但占用時間的事件。
- `human_mistake`：人工誤刪、誤字、整體平移或檔案損壞。

一次差異可有多個分類。只有結構差異、沒有原音證據時，不要推論講者、笑聲長度或真實開口。

## 4. 學習層級

每項修正只能放入下列一層：

1. `episode_lock`：立即生效於本集，寫入 `decisions.json`。所有人工確認預設先進此層。
2. `series_rule`：只適用同一 `series_id` 的特定節目、固定主持人、來賓、用語或錄音習慣，寫入 `series-profile.json`。不得包含單集時間碼、素材、逐句鎖定或待確認內容。
3. `global_candidate`：可能適用所有字幕，但證據尚不足，聚合到 `learning-registry.json`。
4. `global_confirmed`：已通過門檻和回歸測試，寫入 SKILL、style guide、程式或測試。
5. `conflict`：存在互斥修正、意圖不明或疑似人工誤改，暫不套用到其他工作。

同一修正可以同時建立 `episode_lock` 與一筆較高層候選；但未升格前不得影響其他節目。

## 5. 升格與降級

低風險機械規則包括固定格式、明確專有名詞拼法、解析與驗證錯誤，例如「每個 SRT 區塊只能有一行文字」。符合以下全部條件可自動升格：

- 至少 3 次獨立修正。
- 橫跨至少 2 個 `job_id`。
- 沒有相反證據。
- 至少 2 位校對者，或內容負責人已明確確認。
- 有可自動重現的正例與反例。
- 新舊全部回歸測試通過。

高判斷規則包括語意刪留、語助詞功能、笑聲是否獨立、講者歸屬、多人內容取捨、自然切句、字幕起訖與任何會刪內容的規則。即使重複出現，也只建立候選；必須由內容負責人明確確認後才升格。自然切句升格後也只能建立判斷順序、警示與回聽要求，不得假裝用固定字數或簡單正則取代語意判斷。

內容負責人說「以後都這樣」「永久規則」「全節目適用」時，可直接決定作用域，但仍必須新增回歸測試。只說「這裡改成」時一律視為本集修正。

已升格規則若出現可信反例，先降為候選或縮小為節目規則，不要用更多例外硬補。記錄被取代規則及原因，防止未來回退。

## 6. 多剪輯師治理

- 記錄校對者但不依個人資歷決定真偽。
- 單一校對者的修改可鎖定本集，不可單獨建立全域高判斷規則。
- 同一位置若不同校對者給出不同答案，標成 `conflict` 並保留兩邊原文、時間點、音訊證據和作用域。
- 禁止 last-write-wins。只有內容負責人的最新明確決定可解決全域衝突。
- 純軟體重排、重新編號、換行、編碼或整體固定偏移，不得當成風格學習證據。
- 若人工稿疑似損壞或錯集，先交付差異摘要並請確認，不更新 Skill。

## 7. 回歸測試

每次人工回填都要：

1. 驗證人工 SRT 可解析、編號連續、時間不重疊。
2. 驗證每個字幕區塊恰好一行文字；若有實體換行，先以半形空格保留語句邊界後再驗證。
3. 把人工確認寫入本集 `decisions.json` 並以 `exact` 保護文字、start 與 end；不能只鎖起點。對應 XML 案件依 [切點審查落實](reviewed-cut-release.md) 保存人工稿與成品 SHA256，明確區分人工重放與獨立生成驗證。
4. 重跑本集驗證，確認沒有把人工內容改回。

每次全域升格還要：

1. 新增最小失敗案例，能重現本次問題。
2. 新增至少一個反例，證明規則不會過度套用。
3. 執行 `scripts/test_srt_style.py` 與 `scripts/test_revision_report.py`。
4. 用既有人工鎖定案例回歸；任何確認內容被改動即視為失敗。
5. 從可信上游稿重建，不在錯誤成品上繼續補丁。

程式只能自動化可客觀驗證的規則。語意與講者判斷應寫成決策流程與測試案例，不要假裝用簡單正則就能取代回聽。

## 8. 回報格式

每次收到人工稿後，用簡短固定格式回報：

- 工作編號與校對者
- 人工變動總組數
- 各分類數量
- 本集新增鎖定數
- 節目規則或專有名詞更新
- 新增全域候選
- 已升格的全域規則
- 衝突或仍需確認項目
- 驗證 errors 與 warnings

若沒有規則升格，說明已保存為本集鎖定或候選。不要把「看過差異」描述成「Skill 已永久學會」。
