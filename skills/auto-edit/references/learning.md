# 人工定案的分層回填

使用者指定人工版本並要求學習，才建立定案差異；交付成功或 AI 自己的修改不是偏好證據。先驗證當案、原稿／人工稿、hash 與配套 XML/SRT；保留不可變基準及人工鎖定。舊案例完整證據保留原位置，知識倉庫只收精簡索引與可重用規則。

每項差異記錄：id、觀察與原因、source（case_id、檔案 hash、位置、使用者確認）、scope、primary、status、promotion_reason、supersedes/conflicts_with、驗證範圍。一次修改含多種事實時拆成原子項；每個可重用規則只有一個主要位置。單集鎖定與較高層候選可以並存，但引用同一證據，不能算兩次獨立學習。

|歸屬|判準|主要位置|
|---|---|---|
|common|不依客戶的素材／交換／驗證技術原則，或明確要求全案適用|common.json 或專責工具的既有規格（此處引用）|
|client|內容負責人確認對該客戶各类型均適用的品牌／詞彙／工作偏好|clients/<id>/client.json|
|type|僅此客戶某影片類型的節奏、旁白、聲音與字幕偏好|clients/<id>/types/<type>.json；已有專責來源則引用|
|episode|精確時間、片長、效果比例、人物、片段改字、單集例外或證據不足|案件 decisions／學習紀錄；不升格|

不能因同屬品牌就把口播固定講者放到 GoPro 現場，不把短／長格式當剪輯類型。同客戶多集觀察不足以證明所有客戶通用。先決定作用域再決定存檔，不按看到的來源資料夾直接歸類。

狀態為 confirmed / starting_preference / candidate / conflict / superseded。人工單集 final 預設只確認本集；既有經使用者要求整理的系列起始偏好可保留 starting_preference，不能改名永久硬規則。客戶通用偏好證據不足時保持空集合並指出缺口。

通用技術修復用正例／反例驗證後回填工具主來源。語意、講者、節奏、刪留等高判斷規則需內容負責人明確確認作用域；機械字幕規則沿用字幕 learning-loop 的門檻，跨字幕路線共用升格時採較嚴的跨兩個獨立客戶／系列門檻，不削弱既有規範。明確的本次使用者規則優先，但不能讓不支援的引擎聲稱支援。

先查所有層相同概念，合併到單一 primary；其餘變成 ID 引用。較低層只可明示縮小適用範圍或覆蓋可調偏好，記錄被覆蓋 ID 與理由。保留來源完整性、人工鎖定及時間映射契約。相同範圍互斥且無最新明確決定時標 conflict，保留兩邊並集中詢問；不按檔案修改時間覆蓋。可信反例出現時縮小／降級，記 supersedes，避免再度升回。

完成差異回填後：本集鎖定不回退；其他客戶／類型反例不受影響；來源與測試可重現；明確列新增／合併／候選／衝突／未升格項。更新各規則主要來源後，執行相關回歸與隱私檢查，明確提交本次檔案並依所屬倉庫的正常同步流程推送；公開分享只含已審查的通則及合成範例。
